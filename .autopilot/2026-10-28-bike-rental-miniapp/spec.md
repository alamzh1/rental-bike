# Спецификация: Аренда Байка — Telegram Mini App (MVP)

## Задача

Турист в Куинёне хочет взять байк на свои даты и не переписываться с прокатом: не понятно, что свободно, сколько выйдет за весь срок, как заплатить без вьетнамского счёта и что нужно из документов. Владелец проката хочет получить предоплату до выдачи, не допустить двойных броней и видеть свой парк и загрузку в одном месте.

## Решение

Клиент открывает приложение из бота, выбирает даты одним касанием, видит только свободные байки с ценой за весь срок, бронирует на одном экране и платит VietQR или наличными при получении — всё внутри Telegram, на русском, английском или вьетнамском. Бот подтверждает бронь и напоминает о выдаче и возврате. Менеджер на точке выдаёт и принимает байк по QR с фотоактом прямо в том же приложении. Владелец ведёт парк, цены, брони и шахматку в веб-админке.

Без аккаунтов платёжного сервиса и бота всё работает в тестовом режиме: оплата подтверждается тестовой кнопкой, сообщения бота пишутся в лог. Ключи из `.env` включают настоящие.

## Решения по реализации — дополнение после проверки

- **Админка** — Refine (headless) + React + Vite + Tailwind по рекомендации ТЗ §10.1; UI свой на токенах дизайн-системы.
- **Резерв байка при создании брони** — механизм защиты от двойной брони (exclusion constraint работает по байку); клиенту байк не показывается, менеджер переназначает при выдаче — бронь по-прежнему на модель, как в ТЗ.

## Решения по реализации

- **Монорепозиторий pnpm** — один язык (TypeScript) для Mini App, админки, API и бота; общие типы и расчёт цены не расходятся между клиентом и сервером.
- **Mini App** — React 18 + TypeScript + Vite, `@telegram-apps/sdk-react`, TanStack Query, i18next, Tailwind с токенами из `design-system/tokens.css`. Ленивая загрузка всех экранов кроме главной — ради ≤ 250 КБ.
- **Админка** — React + Vite + TanStack Query + Tailwind, те же токены; без Refine — его вес и абстракции не окупаются на 9 разделах.
- **API** — NestJS + Prisma + PostgreSQL 16. Exclusion constraint `EXCLUDE USING gist (bike_id WITH =, period WITH &&)` на занятые интервалы с буфером — единственная надёжная защита от двойной брони; создание брони — транзакция: выбор свободного байка модели `FOR UPDATE SKIP LOCKED` + вставка, конфликт → 409.
- **Бронь на модель, байк закрепляется при выдаче** — по ТЗ; при создании брони сервер резервирует любой свободный байк модели (это и есть защита), менеджер при выдаче может переназначить на другой свободный.
- **Очереди** — BullMQ + Redis: отмена неоплаченных через 15 мин, напоминания, сводка 20:00, очистка документов, курс валют раз в сутки.
- **Бот** — grammY внутри API-процесса (модуль), long polling в dev, webhook в prod; без токена — `LogNotifier`.
- **Оплата** — интерфейс `PaymentProvider`; `PayOsProvider` (VietQR через payOS, проверка подписи webhook) и `TestProvider` (QR-заглушка + `POST /dev/payments/{id}/pay`, только в dev); наличные — без провайдера, отметка менеджера.
- **Файлы** — S3-совместимое хранилище (MinIO локально), два бакета: публичный для фото моделей, приватный для документов и фотоактов.
- **Курс валют** — адаптер `RatesProvider`; по умолчанию фиксированные курсы из настроек (VND→RUB, VND→USD), правятся в админке; внешний источник — подключаемый.
- **Договор PDF** — `pdfkit` со встроенным шрифтом с вьетнамской диакритикой и кириллицей (Manrope / Be Vietnam Pro); текст — шаблон из настроек.
- **Авторизация** — Mini App: заголовок `Authorization: tma <initData>`; админка: Telegram Login Widget → сессия; в dev — `DEV_AUTH=1` с тестовыми пользователями (клиент, менеджер, админ), выключено в prod.
- **Деньги** — целые VND; **время** — UTC в БД, отображение в часовом поясе точки.
- **Дизайн** — скилл impeccable: `DESIGN.md` на основе `design-system/`, затем экраны по нему; финальный проход impeccable audit + polish.
- **Фото** — генерация через Higgsfield CLI (пользователь разрешил тратить кредиты), конвертация в WebP/AVIF нескольких размеров.
