# Инструкция администратора

Админка — сайт по адресу `ADMIN_URL`. Работает с телефона и компьютера, язык интерфейса RU/EN/VI переключается в меню.

## Вход и роли

- Вход без номера телефона: кнопка «Войти через Telegram» или QR на странице входа открывают бота, вход подтверждается кнопкой в чате, и страница открывается сама. Запасной способ — Telegram Login Widget, он один раз просит номер. Регистрации нет: роль определяется по Telegram ID. Язык выбирается на странице входа.
- **Администратор** — все разделы. Список ID — переменная `ADMIN_TELEGRAM_IDS` в `.env` (через запятую), задаётся при деплое.
- **Менеджер точки** — назначается в разделе «Точки» → «Менеджеры» по числовому Telegram ID. Менеджер видит брони и парк своей точки, а в Mini App ему открывается «Режим менеджера» ([инструкция менеджера](manager-guide.ru.md)). Снять менеджера — там же; доступ пропадает сразу.
- **Владелец точки** — назначает администратор в разделе «Точки» → «Владелец» по Telegram ID (человек узнаёт его командой `/id` в боте). Видит только свою точку: брони, парк, финансы, цены, платежи, менеджеров и счёт оплаты. Общие настройки, тексты, баннер и журнал ему закрыты.
- Администратор переключает обзор селектором «Точка» над разделами: выбранная точка сужает все разделы, новые модели и расходы попадают в неё.
- **Контроль владельцев** — раздел «Владельцы», только администратор: доход, просрочки, случаи «байка нет», несделанные возвраты, выдачи без фотоакта и последняя активность по каждой точке. Кнопки переводят всю админку на точку, журнал показывает действия её сотрудников. Бот сообщает администратору, если точка не ответила клиенту, ответила «байк на месте», удержала депозит или владелец сменил счёт оплаты.
- **Фотоакты** — раздел с фото до и после каждой аренды: владелец видит только свою точку, файлы приватные и не удаляются. Выдача и завершение брони возможны только через акт с 4–8 загруженными фото.
- Сессия админки живёт 12 часов, «Выйти» — в меню.
- В dev-режиме на странице входа есть тестовый вход (администратор / менеджер / владелец) — в production его нет.

## Первый запуск: что заменить

Сид создаёт демо-данные с плашкой **«ДЕМО»**. До приёма клиентов:

1. **Парк → Модели**: настоящие модели, характеристики, описания на трёх языках (без перевода клиент видит EN), фото. Демо-модели удалите или скройте.
2. **Парк → Байки**: каждый байк с госномером, пробегом, статусом; документы байка (регистрация, страховка).
3. **Парк → Бренды**: логотипы, если есть (без логотипа бренд показывается текстом).
4. **Цены**: тарифы по длительности для каждой модели (строки подряд, первая — с 1 суток, пустое «До» в последней — без границы), сезоны с коэффициентом, опции (за день или разово).
5. **Точки**: адрес, точка на карте, часы работы (сейчас 08:00–20:00 — значение по умолчанию из ТЗ, не подтверждено), часовой пояс, менеджеры.
6. **Тексты**: договор аренды, правила аренды, политика конфиденциальности, вопросы и ответы — на трёх языках. Сейчас там заглушки.
7. **Настройки**: контакт менеджера (для кнопки «Связаться»), цена доставки в отель, депозит деньгами или документом, курсы RUB/USD.

## Разделы

| Раздел | Что делать |
|---|---|
| **Сводка** | Выдачи и возвраты сегодня, загрузка парка, брони, ждущие оплаты, выручка за день / неделю / месяц, воронка «открыли → оплатили» и источники открытий. |
| **Брони** | Поиск по коду, телефону, имени; фильтры по статусу и датам. В карточке брони — клиент, документы (ссылка открывается на 10 минут), акты выдачи и возврата с фото, платежи. Можно сменить байк (только свободный той же модели) и статус по правилам переходов. **Новая бронь** — ручная, например клиент «с улицы» или по телефону. |
| **Шахматка** | Байки по строкам, дни по столбцам: видно занятость и окна. Конфликт при переносе — сообщение «Байк занят». |
| **Парк** | Модели, байки, бренды. Байк в статусе «Ремонт» с датой готовности не попадает в доступные. |
| **Цены** | Тарифы, сезоны, опции. Цена в Mini App пересчитывается сразу после сохранения. |
| **Точки** | Адрес, карта, часы, часовой пояс, менеджеры. |
| **Платежи** | «Сверка» — ожидалось / получено по броням, расхождения; «Транзакции» — все оплаты, наличные, возвраты; «Удержания» — из депозита при возврате. Возврат клиенту: кнопка возврата у платежа, сумма не больше оплаченной; после перевода денег отметьте возврат выполненным. |
| **Тексты** | Юридические тексты и правка **любой строки интерфейса** на трёх языках поверх стандартных переводов — без деплоя. |
| **Настройки** | Правила работы (см. ниже). Применяются сразу, перезапуск не нужен. |
| **Баннер** | Один баннер на главной Mini App: заголовок и текст на трёх языках, картинка, ссылка, «Показывать на главной». |
| **Журнал** | Кто, что и когда изменил (только администратор). |

## Настройки и их смысл

| Настройка | По умолчанию | Что значит |
|---|---|---|
| Удержание неоплаченной | 15 мин | Сколько бронь VietQR ждёт оплату, потом отменяется, байк освобождается |
| Буфер после брони | 60 мин | Осмотр и мойка: байк занят после конца брони |
| Минимум до выдачи | 60 мин | Клиент не забронирует ближе к выдаче (ручную бронь не ограничивает) |
| Минимальный срок | 1 сутки | Меньше — бронь не оформится |
| Неявка через | 3 ч | Подтверждённая, но не выданная бронь отменяется системой |
| Отмена клиентом | > 24 ч — 100 %, 2–24 ч — 50 %, < 2 ч — 0 | Процент возврата аренды; депозит возвращается полностью |
| Опоздание с возвратом | запас 60 мин, после — почасовая доплата, после 4 ч — ещё сутки по тарифу | Сумма почасовой доплаты — **впишите свою** |
| Депозит | деньгами | Деньгами — депозит модели добавляется к оплате и возвращается после сдачи; документом — клиент оставляет документ на точке |
| Предоплата при наличных | 0 % | 0 — бронь наличными подтверждается сразу; больше 0 — клиент платит эту часть через VietQR |
| Хранить документы | 90 дней | После последней брони клиента документы удаляются |
| Курсы RUB/USD | демо-значения | Для пересчёта «≈ ₽ / $»; оплата всегда в донгах |

## Каждый день

- Утром — «Сводка»: выдачи и возвраты на сегодня, брони, ждущие оплаты; в «Брони» — фильтр по статусу «Проблема» (например, сумма перевода не совпала).
- Бот присылает менеджеру новые брони и в 20:00 — список выдач на завтра; в `ADMIN_ALERT_CHAT_ID` (если задан) приходят алерты об ошибках оплаты.
- Раз в неделю — «Платежи → Сверка» с выпиской payOS.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Клиент заплатил, бронь не подтвердилась | «Платежи → Сверка»: если платёж пришёл с другой суммой — бронь в «Проблема», решите с клиентом (доплата или возврат). Если платежа нет — проверьте webhook payOS и `PAYOS_WEBHOOK_IPS` ([деплой](deploy.md#4-обратный-прокси-https-и-trust-proxy)). |
| Байк сломался перед выдачей | «Парк → Байки» → «Ремонт» с датой; брони на эту модель переназначьте в «Брони» на другой байк или свяжитесь с клиентом. |
| Нужно отменить бронь за клиента | Карточка брони → статус «Отменена»; возврат — в «Платежи». |
| Перевод выглядит неправильно | «Тексты» → найдите строку и исправьте на нужном языке. |

Резервные копии и восстановление — [restore.md](restore.md).
