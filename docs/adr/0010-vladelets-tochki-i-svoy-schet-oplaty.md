# 0010. Владелец точки и свой счёт оплаты у каждой точки

## Контекст
Прокат растёт на нескольких арендодателей. Каждый должен видеть только свои данные, а деньги клиентов не должны проходить через владельца платформы.

## Решение
Новая роль `OWNER` привязана к одной точке через `User.locationId`, как менеджер, и получает суммы, цены и финансы. Всю видимость по-прежнему задаёт `staff-scope.ts`. Администратор может сузить обзор до одной точки заголовком `x-admin-location`: заголовок действует только на роль ADMIN.

Ключи payOS хранятся в `Location`, API Key и Checksum Key зашифрованы (`PAYMENT_KEYS_SECRET`). У точки свой адрес `/api/webhooks/payos/:locationId`. Платёж запоминает счёт, на котором создан (`raw.account`), и подпись счёта подтверждает только его платежи. Точка без ключей работает через общий провайдер из `.env`.

## Почему
Деньги сразу у арендодателя: платформа не становится посредником в расчётах. Проверка счёта платежа обязательна: владелец знает свой ключ подписи и иначе мог бы подтвердить бронь чужой точки, подставив номер её заказа.

## Последствия
Комиссию платформы приложение не удерживает. Смена `PAYMENT_KEYS_SECRET` требует ввести ключи всех точек заново. Смена домена требует заново сохранить ключи, чтобы payOS получил новый адрес webhook. Владелец с двумя точками пока невозможен.
