# 0009. D01 — хранилище в dev: LocalStorage вместо MinIO

## Контекст
План предполагал, что локальная инфраструктура поднимется в compose вместе с MinIO как S3-хранилищем. Сборка доказала: официальные образы MinIO в Docker Hub больше не публикуются, а сторонний образ использовать запрещено.

## Решение
У `Storage` две реализации. `LocalStorage` пишет в папку `storage/` в корне (в `.gitignore`); публичные файлы отдаёт API по `/files/public/*`, приватные — только по подписанной ссылке с TTL ≤ 600 с. Выбор по окружению: заданы `S3_ENDPOINT` и ключи — `S3Storage`, иначе `LocalStorage`. MinIO остаётся в compose по желанию через `MINIO_IMAGE`.

## Почему
- Сторонний образ MinIO отвергнут: правило запрещает неофициальные образы, а проверить его происхождение нельзя.
- Сборка MinIO из исходников отвергнута: непропорциональная цена для dev-окружения.
- Объектное хранилище в облаке для dev отвергнуто: запуск должен идти одной командой без аккаунтов (0005).
- Интерфейс `Storage` уже был в плане, поэтому добавление второй реализации не ломает вызывающий код.

## Последствия
- В dev не проверяется настоящее поведение S3: серверное шифрование (SSE), политики бакетов и настоящие presigned URL. Эти пункты проверяются только на реальном S3.
- Подписанные ссылки `LocalStorage` делает сам API, его логика подписи — ещё один кусок безопасности, который надо поддерживать и тестировать.
- Тесты и документация, ссылавшиеся на «локальный MinIO», расходятся с реальностью; интеграционные тесты хранилища идут на `LocalStorage`.
- Выбор реализации по наличию `S3_*` значит, что неполная настройка в проде молча даст локальную папку, а не ошибку.
