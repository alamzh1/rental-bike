# 0005. Внешние сервисы только через адаптеры, тестовый режим по умолчанию

## Контекст
Аккаунтов payOS и токена бота на момент сборки нет, их создаст владелец сам. Систему всё равно надо запускать и проверять целиком.

## Решение
Платежи, бот, курсы и хранилище скрыты за интерфейсами: `PaymentProvider`, `Notifier`, `RatesProvider`, `Storage`. Для каждого есть реальная и тестовая реализация (`PayOsProvider` / `TestProvider`, `GrammyNotifier` / `LogNotifier`). Переключение — только через `.env`. `TestProvider` разрешён только при `NODE_ENV=development|test`; вне dev без ключей `PAYOS_*` подставляется `DisabledProvider` (оплата отвечает 503 `PAYMENT_NOT_AVAILABLE`).

## Почему
- Прямые вызовы payOS и Telegram из бизнес-кода отвергнуты: нельзя ни запустить сборку без аккаунтов, ни писать тесты без сети.
- Тестовый провайдер, доступный в любом окружении, отвергнут: кнопка «Оплатить (тест)» в проде позволяет бесплатно подтверждать брони. Поэтому вне dev безопаснее отказать в оплате, чем молча принять.

## Последствия
- Реальная интеграция с payOS и Telegram не проверена живыми аккаунтами; приёмка этих пунктов идёт через тестовый режим.
- Любой запуск e2e и любые проверки должны идти с переменными из `scripts/env-defaults.mjs` (`NODE_ENV=development`), иначе оплата не заработает.
- Каждый новый внешний сервис обязан получить интерфейс и тестовую реализацию, это постоянная цена на каждую интеграцию.
- Вебхук payOS проверяется подписью, идемпотентен по внешнему ID; при заданном `PAYOS_WEBHOOK_IPS` — ещё и по IP.
