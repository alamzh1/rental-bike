# 0003. Монорепозиторий pnpm на TypeScript и единая `quote()`

## Контекст
Нужны Mini App, веб-админка, API и бот. Цена и правила дат должны совпадать у клиента и сервера: сумма в кнопке «Забронировать · 910 000 ₫» обязана равняться сумме в QR.

## Решение
Один репозиторий pnpm, везде TypeScript strict. Пакет `shared` владеет правилами: расчёт цены, опоздание, процент возврата, машина статусов, код брони. Он не знает ни о БД, ни о HTTP. API и клиент вызывают одну и ту же чистую функцию `quote()`.

## Почему
- Расчёт отдельно на сервере и на клиенте отвергнут: две реализации рано или поздно разойдутся, а расхождение в деньгах — это спор с клиентом.
- Расчёт только на сервере отвергнут: итог под календарём должен пересчитываться мгновенно при выборе дат, без запроса на каждое касание.
- Разные языки для API и фронта отвергнуты: тогда общий пакет невозможен.

## Последствия
- Правило цены меняется в одном месте, но сразу влияет на клиент, сервер и тесты; покрытие `shared` обязано быть ≥ 80%.
- `shared` и `i18n` собираются как ESM, API подключает их собранный `dist`: требуется Node ≥ 20.19 и сборка пакетов перед запуском API.
- Параллельные исполнители делят пакет по файлам (по файлу на модуль API), иначе конфликты правок.
- Привязка к одному стеку: уйти от Node/TypeScript на серверной стороне означает потерять общий код.
