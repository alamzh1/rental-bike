# Приёмка MVP по §13.2 ТЗ

Как проверен каждый критерий. Живые аккаунты (бот, payOS) и реальные устройства в сборке не использовались: такие пункты проверены тестовым режимом — `TestProvider` вместо payOS, `LogNotifier` вместо бота, браузер Chromium с эмуляцией телефона 360 px вместо Telegram на iOS/Android/Desktop (история 59). Что остаётся проверить на живых аккаунтах — последний столбец.

Команды: `pnpm check` (типы, линтер, unit, интеграционные тесты на настоящем PostgreSQL 16, лимит размера), `pnpm e2e` (Playwright: Mini App + API с отдельной БД `<POSTGRES_DB>_e2e`, тестовая оплата).

## Что нужно от владельца

Из «Открытых мест» спецификации — без этого MVP работает только на демо-данных и в тестовом режиме:

- Реальный парк: модели, байки с госномерами, цены, тарифы, депозиты (сейчас «ДЕМО»).
- Часы работы точки (сейчас 08:00–20:00 по умолчанию ТЗ), цена доставки в отель, почасовая доплата за опоздание.
- Telegram-username менеджера, тексты договора, правил аренды, политики конфиденциальности, FAQ на трёх языках.
- `TELEGRAM_BOT_TOKEN`, `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY`, `ADMIN_TELEGRAM_IDS`; по желанию `SENTRY_DSN`, `PAYOS_WEBHOOK_IPS`, `ADMIN_ALERT_CHAT_ID`.
- Логотипы брендов, вычитка вьетнамских (и русских) переводов носителем.
